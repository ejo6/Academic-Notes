## Highlights of Hardware 
### Basic Early Computers
- Konrads Zuse's Z3 (1941, Germany) was the first Turing complete computer, but conditional jumps were missing. Mechanical
- Colossus (1941, UK) was first programmable, not Turing complete. Non-mechanical so it was a lot faster
- Harvard Mark I - IBM ASCC (1944). Electro mechanical. No conditional jumps and not Turing complete. Could do basic math operations
- ENIAC in 1945 was the first general purpose electronic computer. Could run 5000 cycles per second for operations on 10 digit numbers. Not binary - using actual decimal

### Personal Computers
- IBM PC introduced on August 12. Storage was a floppy disc

## Modern Computer Architectures
### Von Neumann
![[Screenshot 2026-09-09 at 9.48.40 AM.png|253]]
Used a shared memory for instructions and data. Modern computers, especially with resepect to what software sees use this model

### Harvard Architecture
![[Screenshot 2026-09-09 at 9.50.16 AM.png|433]]
- Seperates memory banks and channels for instructions and data
- Good because it lets you use instructions as read-only, where the Data pools has read and write

### Multi Core Architecture
![[Screenshot 2026-09-09 at 9.52.40 AM.png|354]]
Modern multi-core processors see a varying hierarchy of independent and shared memories
- L1 is split by instructions and data
- L2 is a unified cache which has both instructions and data
- For cores, 2 of them share an L2 cache
	- Sometimes we have an L3 cache that all cores can access
- The main memory is shared by everything

## System and Hardware Abstractions
### Components of a Computer
We use the same components below for all kinds of computer including desktops, server, supercomputer, embedded, etc.
![[Screenshot 2026-09-09 at 10.09.31 AM.png|413]]
### Layers of Software
**Application software**
- written in a high level language
- Javascript, Python, Java
**System software**
- Compiler: translates HLL code to machine
- Operating system: service code
	- Handing I/O
	- Managing memory and storage
	- Scheduling tasks
**Hardware**
- Processor, memory, I/O controllers

### Levels of Program Code
**High-level language**
- Level of abstraction closer to problem domain
- Provides productivity and portability
**Assembly language**
- Textual representation of machine instructions
- This is where most of the optimizations can take place
	- EX: Fixing a loop that is just doing the same thing every time
**Hardware representation**
- Straight machine code
- At this point this is machine dependent, different for AMD and intel

4. Performance via parallelism 
	- Fork threads off to do processes in parallel 
5. Performance via pipelining

6. Performance via prediction
